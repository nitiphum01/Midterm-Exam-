# API Contract — Campus Equipment Booking API

All requests and responses are JSON.

| Environment | `BASE_URL` |
|---|---|
| Local (`npm run dev`, local D1) | `http://localhost:8787/api` |
| Deployed (Cloudflare Workers + remote D1 `booking-db`) | `https://equipment-booking-api.nitiphumhon.workers.dev/api` |

`BASE_URL` itself is not a route: `GET /api` returns `404 {"error":"Route GET /api not found"}` (no extra routes were added beyond the contract).

## Equipment

| Method | Path | Success | Errors |
|---|---|---:|---|
| GET | `/equipment` | 200 — array of `{ id, name, location }` | — |

Seed data (read-only):

```json
[
  { "id": "eq-1", "name": "Projector A", "location": "Building 1" },
  { "id": "eq-2", "name": "Camera B", "location": "Building 2" },
  { "id": "eq-3", "name": "Meeting Room C", "location": "Building 3" }
]
```

## Bookings

| Method | Path | Success | Errors |
|---|---|---:|---|
| GET | `/bookings` (optional `?equipmentId=eq-1`) | 200 — array of bookings, ordered by `startAt` | — |
| GET | `/bookings/:id` | 200 — booking | 404 |
| POST | `/bookings` | 201 — created booking | 400, 409 |
| PATCH | `/bookings/:id` | 200 — updated booking | 400, 404, 409 |
| DELETE | `/bookings/:id` | 204 — no body | 404 |

Extra (not part of the common contract, used only for setup checks): `GET /health` → `200 {"status":"ok"}`.

### Request body

- **POST:** all five fields required.
- **PATCH:** any subset of the five fields (at least one). Sending the full body, as in `curl_test_guide.md` step 5, also works. The patch is merged onto the stored booking and all rules are re-checked on the merged result.

```json
{
  "equipmentId": "eq-1",
  "borrowerName": "Somchai Jaidee",
  "startAt": "2026-10-20T09:00:00.000Z",
  "endAt": "2026-10-20T11:00:00.000Z",
  "purpose": "Class presentation"
}
```

### Booking response

```json
{
  "id": "bk-0b6c…",
  "equipmentId": "eq-1",
  "borrowerName": "Somchai Jaidee",
  "startAt": "2026-10-20T09:00:00.000Z",
  "endAt": "2026-10-20T11:00:00.000Z",
  "purpose": "Class presentation",
  "createdAt": "…",
  "updatedAt": "…"
}
```

- `id` is generated by the server: `bk-` + UUID.
- `startAt` / `endAt` are always returned in UTC `toISOString()` format, even if the request used another offset (e.g. `2026-10-20T18:00:00+07:00` → `2026-10-20T11:00:00.000Z`).

## Validation rules

- `equipmentId` (≤50), `borrowerName` (≤100), `purpose` (≤200): non-empty strings (trimmed).
- `startAt`, `endAt`: ISO 8601 date-time **with timezone** (`Z` or `±HH:MM`), and must be a **real calendar date** (`2026-02-30` is rejected, `2028-02-29` is accepted). Stored normalized to UTC.
- `startAt` must be before `endAt` (also enforced by `CHECK (start_at < end_at)` in the schema).
- `equipmentId` must exist in `equipment`.
- No overlap with another booking of the same equipment: overlap when `existing.startAt < new.endAt AND new.startAt < existing.endAt`. Back-to-back (one ends 11:00, next starts 11:00) is allowed. Checked on **POST and PATCH** (PATCH excludes the booking itself).
- The overlap condition is also part of the `INSERT`/`UPDATE` statement (`WHERE NOT EXISTS …`), so check and write are one atomic statement; if a concurrent request took the slot first, the API returns `409`.
- Unknown fields and malformed JSON are rejected.
- All SQL uses D1 parameter binding (`.prepare(...).bind(...)`); request data is never concatenated into SQL.

## Errors — always `{ "error": "message" }`

| Status | When | Why this code |
|---:|---|---|
| 400 | Missing/invalid field, bad JSON, bad or impossible date, `startAt >= endAt`, unknown `equipmentId` in body, unknown field | The client sent invalid data; fixing the request fixes it. Unknown `equipmentId` is invalid *data* in the body — the URL `/bookings` itself exists, so it is not 404. |
| 404 | `/bookings/:id` does not exist, or unknown route | The resource identified by the URL is not found. |
| 409 | Time range overlaps an existing booking of the same equipment | Request is valid but conflicts with the current state of the server. |
| 500 | Unexpected server error | Details are logged on the server, never returned. |

### Example error responses (from `evidence/`)

| Case | Status | Body |
|---|---:|---|
| `startAt` after `endAt` (G6) | 400 | `{"error":"startAt must be before endAt"}` |
| Missing fields (E3) | 400 | `{"error":"borrowerName is required; purpose is required; startAt is required; endAt is required"}` |
| Unknown equipment (E4) | 400 | `{"error":"equipmentId 'eq-999' does not exist"}` |
| Malformed JSON (E5) | 400 | `{"error":"Request body is not valid JSON"}` |
| Impossible date (E6) | 400 | `{"error":"startAt must be an ISO 8601 date-time with timezone, e.g. 2026-10-20T09:00:00.000Z; …"}` |
| Booking not found (G8) | 404 | `{"error":"Booking not found"}` |
| Overlap (G7, E2) | 409 | `{"error":"Equipment 'eq-1' is already booked in this time range (booking bk-…)"}` |
